GPU-Passthrough Virtualization Lab

KVM/QEMUVFIOIOMMULinuxisolation

Overview

I built a Linux host running KVM/QEMU with a dedicated GPU passed straight through to a virtual machine, giving the guest near-native graphics performance while staying fully isolated from the host. The project was about understanding hardware virtualization, device isolation, and building a disposable environment for malware and reverse-engineering work.

What it involved

  • IOMMU & VFIO: enabled IOMMU, inspected IOMMU groups, and bound the GPU to the vfio-pci driver so the host released it cleanly at boot.
  • Guest configuration: configured the QEMU/libvirt domain with the passed-through GPU, CPU pinning, and hugepages for stable performance.
  • Isolation goals: a snapshot-based, network-segmented guest I can revert — a safe place to detonate samples and run RE tooling without touching the host.
  • Troubleshooting: worked through the usual passthrough pain — group splitting, vendor-reset quirks, and getting the host to hand off the device.

How it maps to security work

Isolated, revertible VMs are the backbone of any malware analysis or detonation lab, and the underlying concepts — device isolation, IOMMU, hypervisor configuration, network segmentation — are core to understanding both virtualization security and how analysts safely study hostile code. It also demonstrates comfort with Linux internals and hardware-level configuration.

Note. Built and run entirely on hardware I own, as a personal lab environment for learning systems and security tooling.

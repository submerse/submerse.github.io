Game Internals & Anti-Cheat Research

C++x86memory analysisDLL injectionhooking

Overview

A reverse-engineering study of a game engine's runtime memory model, done to understand how cheat techniques work mechanically and — more importantly — how anti-cheat systems detect them. The goal was learning low-level Windows internals and RE methodology, not gaining an advantage in live play.

What I built / figured out

  • Memory model mapping: located the entity list and resolved multi-level pointer chains to read player state reliably across game updates.
  • World-to-screen: reimplemented the engine's view matrix math to project 3D positions to 2D screen space (the basis of an ESP overlay).
  • Injection & hooking: used DLL injection and function hooking to intercept and observe engine calls at runtime.
  • Detection surface: documented what each technique exposes to an anti-cheat — handle access patterns, injected modules, hook signatures — and how detection vs. evasion actually plays out.

Selected technique (snippet)

An illustrative slice of the world-to-screen projection — included to show the reasoning, not as runnable cheat software:

// view-matrix projection: world (x,y,z) -> screen (sx,sy)
bool WorldToScreen(const Vec3& pos, const float m[16], Vec2& out) {
    float w = m[12]*pos.x + m[13]*pos.y + m[14]*pos.z + m[15];
    if (w < 0.01f) return false;            // behind the camera
    float x = m[0]*pos.x + m[1]*pos.y + m[2]*pos.z + m[3];
    float y = m[4]*pos.x + m[5]*pos.y + m[6]*pos.z + m[7];
    out.x = (screenW * 0.5f) * (1.f + x / w);
    out.y = (screenH * 0.5f) * (1.f - y / w);
    return true;
}

How it maps to security work

These are the same primitives used in malware analysis and red teaming: reading and writing another process's memory, resolving pointers in a live address space, injecting code, hooking API calls, and reasoning about what a defensive product (here, anti-cheat; in industry, EDR) can observe and how evasion is detected. The project is effectively a hands-on Windows internals and evasion-vs-detection exercise.

Context & ethics. Conducted on my own systems against offline/local targets for the purpose of learning reverse engineering and Windows internals. No software was deployed against live players, and no runnable cheat is distributed here — this page documents technique and analysis only.
